## 1. 测试目标与范围

### 1.1 目标
通过端到端手工测试，验证排班系统核心业务链路（登录 → 基础数据 → 一键排班 → 视图/调整 → 发布 → 员工自助 → 审批）的正确性、权限隔离的有效性，以及关键边界与异常处理的健壮性。

### 1.2 测试范围
| 模块 | 说明 |
|---|---|
| 登录与认证 | 登录、限流、失败锁定、防枚举、忘记密码 OTP |
| 角色与权限 | SYSTEM_ADMIN / STORE_MANAGER / EMPLOYEE 三级权限与路由守卫 |
| 基础数据 | 员工 CRUD、技能矩阵、工作站、班次、高峰时段、人数需求（含 Excel 导入导出、类型复制、AI 识别） |
| 规则配置 | 规则修改权限、版本管理 |
| 排班核心 | 一键生成、周期覆盖、周/月/日视图、手动调整、拖动、发布、删除 |
| 报表合理度 | 合理度趋势、问题汇总、环形图、明细筛选 |
| 员工自助 | 我的班表、请假/审批/提前返岗、换班/审批、站内通知 |
| 审计与看板 | 数据看板、审计日志 |
| 边界与异常 | 参数校验、401/403/404、无效 Token |

### 1.3 不在本次范围
- 后端单元测试（186 个用例已通过，见 docs/测试报告.md）
- 性能/压力测试、并发压测
- AI（DeepSeek）识别准确率评估（仅验证接入与错误处理）
