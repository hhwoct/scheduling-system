## Critical（2）

### C1. init 建表 CHECK 约束与种子 INSERT 矛盾 → 全新部署必然失败
- database/init_shift_mvp.sql:190/565
- staffing_requirements 建表即声明 CHECK (ideal_count >= required_count)，但种子 INSERT 只写 required_count（ideal 落 DEFAULT 0），MySQL 8.0.16+ 在 INSERT 时即抛 ERROR 3819 中断。
- 建议：CHECK 移到第 595 行回填之后再 ADD CONSTRAINT（与 20260819_add_ideal_count.sql 的「先加列→回填→再加 CHECK」一致）。

### C2. 忘记密码仅凭「姓名+手机号」即可重置 → 账号接管
- AuthService.cs:156-197（前端 LoginView.vue 同款风险）
- 无 OTP/验证码/带外验证；GenerateOtp/ValidateOtp 是无人调用的死代码。种子数据全员手机号同一占位值 12312341234，知道姓名即可重置任意员工（含带档案的管理员）密码。
- 建议：恢复 OTP 链路（发码→校验→重置）；种子手机号改唯一值或 NULL 并禁止占位值重置。

## High（8）

### H1. JWT 声明不回读数据库 → 降权/调店后旧令牌仍越权
- Program.cs:123 / CurrentUser.cs:35
- OnTokenValidated 只复核 Status/PasswordVersion/门店状态，不回读 role/store_id；旧令牌最长 7 天内保留旧角色旧门店。
- 建议：比对 user.Role/StoreId 与令牌声明，不一致 context.Fail。

### H2. 密码哈希迁移非幂等 → 重跑覆盖用户已改密码
- migrations/20260811_fix_password_hashes.sql:31-61
- 无条件重写 25 个账号哈希为已知明文（Admin@123456/工号@123456），无「仅占位哈希」守卫。
- 建议：加 LENGTH(password_hash) <> 60 OR NOT LIKE '$2%' 守卫；部署后轮换。

### H3. 日明细次日凌晨（00:00-05:30）写操作未加一天 → 数据写错日期
- ScheduleView.vue:963,988（同 723,905,916,1275,1520,1597,1645）
- isNextDay 时段所有写路径（改休/批量/加人/平移/取消/拖动）用基准日期作 workDate，可能污染前一晚班次。
- 建议：统一 helper：workDate = addDays(base, slot.isNextDay ? 1 : 0)。

### H4. 拖拽移动工作段功能整体失效
- ScheduleView.vue:601,657,666
- updateDragGhost 引用未定义的 rows；入口 onChipMouseDown 未绑定到色块（模板只有 @click/@dblclick）。
- 建议：绑定 @mousedown.stop 并修正 rows 取值，或删除死代码与误导文案。

### H5. MoveSegmentAsync 汇总重算对已平移时段二次叠加 delta
- ScheduleService.cs:1248
- 时段在 1226 行已被改写 +delta，1248 行 .Concat(segmentRows.Select(x => x.TimeSlot + delta)) 再加一次 → 起止时间算错 2×delta。
- 建议：改为 Select(x => x.TimeSlot)。

### H6. 日明细凌晨需求营业日口径与合理度/缺口重算矛盾
- ScheduleService.cs:518-525（GetDailyViewAsync）
- 凌晨 <06:00 应取前一天 day_type（rationality 与 RecalculateGapIssuesAsync 均如此），此处全时段用当天类型。
- 建议：需求查询按 06:00 边界拆分为两种 day_type。

### H7. 「夜班后最少休息」规则读入但从未执行（死配置）
- SchedulingEngine.cs:311 / SchedulingModels.cs:72,304,308
- min_rest_hours_after_night_shift（缺省 10h）加载后无任何消费者，IsNightShift 等均为死代码。夜班员工次日清晨仍可被排班。
- 建议：在 ShiftAllocator 候选过滤中校验「前一日夜班结束时间 → 当日班次开始 ≥ 最小休息小时」，或移除死代码并文档标注未实现。

### H8. 发布「强制确认」分支吞掉真实发布失败
- ScheduleGenerateView.vue:486-493
- publishSchedule 抛错被当作「用户取消」静默返回，计划实际未发布且无提示。
- 建议：拆两步（先 confirm 后单独 try/catch publish + ElMessage.error）。
