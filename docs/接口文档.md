## 通用约定

### 认证方式
- 除登录/健康检查外，所有接口需携带请求头：
  ```
  Authorization: Bearer {token}
  ```
- Token 有效期 24 小时，通过 `POST /auth/login` 获取；前端 15 分钟无操作自动退出登录。

### 响应统一格式
所有接口返回统一信封：

```json
{
  "success": true,
  "message": "操作成功",
  "data": { },
  "errorCode": null
}
```

| 字段 | 说明 |
|------|------|
| `success` | 是否成功 |
| `message` | 提示信息 |
| `data` | 业务数据 |
| `errorCode` | 业务错误码（成功为 null） |

### HTTP 状态码
| 码 | 含义 |
|----|------|
| 200 | 成功 |
| 400 | 参数错误（业务异常） |
| 401 | 未登录 / Token 失效 |
| 403 | 无权限 |
| 404 | 资源不存在 |

### 角色说明
| 角色 | 简称 | 权限 |
|------|------|------|
| SYSTEM_ADMIN | 系统管理员 | 全部 |
| STORE_MANAGER | 门店经理/店长 | 管理端（规则只读） |
| EMPLOYEE | 员工 | 员工端 |
| 兼职（is_parttime=1） | 兼职员工 | 员工端 + 仅低技能岗位排班 |

## 认证接口

### 1.1 登录
`POST /auth/login`

请求：
```json
{ "username": "admin", "password": "Admin@123456" }
```

响应 data：
```json
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "expiresAt": "2026-08-13T17:00:00Z",
  "user": { "id": 1, "storeId": 1, "username": "admin", "nickname": "系统管理员", "role": "SYSTEM_ADMIN" }
}
```

限流：1 分钟 5 次。

### 1.2 发送密码重置验证码
`POST /auth/send-reset-otp`

请求：`{ "username": "E001" }`

响应 data：`{ "devOtp": "123456" }`（生产环境将通过短信下发，开发模式返回 OTP 便于调试）

限流：15 分钟 3 次。

### 1.3 忘记密码（重置）
`POST /auth/forgot-password`

请求：
```json
{
  "username": "E001",
  "verifyInfo": "13800000001",
  "otpCode": "123456",
  "newPassword": "NewPass123",
  "confirmPassword": "NewPass123"
}
```

### 1.4 获取当前用户
`GET /auth/me`

响应 data：`{ "id": 1, "storeId": 1, "username": "admin", "nickname": "系统管理员", "role": "SYSTEM_ADMIN" }`

## 排班计划

### 8.1 一键生成排班
`POST /schedules/generate`（AdminOnly）

请求：
```json
{ "startDate": "2026-09-01", "endDate": "2026-09-30", "planName": "9月排班" }
```

响应 data：
```json
{
  "planId": 30, "planName": "9月排班",
  "restDayCount": 132, "shiftAssignmentCount": 700,
  "workstationAssignmentCount": 2400, "daySummaryCount": 960, "issueCount": 15,
  "issueTypes": ["STAFFING_GAP", "OVERTIME"]
}
```

> 同周期已有 DRAFT 计划时自动覆盖并重新生成；已有 PUBLISHED 则拒绝。

### 8.2 排班计划列表
`GET /schedules?page=1&pageSize=20&status=`（AdminOnly）

响应 data：
```json
{
  "items": [{ "id": 30, "planName": "9月排班", "startDate": "2026-09-01", "endDate": "2026-09-30", "status": "DRAFT", "createdBy": 1, "publishedAt": null, "createdAt": "...", "employeeCount": 30, "issueCount": 15 }],
  "page": 1, "pageSize": 20, "total": 5
}
```

### 8.3 删除排班计划
`DELETE /schedules/{planId}`（AdminOnly）级联删除明细/汇总/问题/换班。

### 8.4 手动调整排班
`PUT /schedules/{planId}/adjust`（AdminOnly）

请求：
```json
{
  "items": [
    { "employeeId": 15, "workDate": "2026-09-03", "timeSlot": "19:00:00", "shiftTemplateId": 4, "workstationId": 10 }
  ]
}
```

### 8.5 发布排班
`POST /schedules/{planId}/publish?force=false`（AdminOnly）

- 存在 ERROR 严重问题时若 `force=false` 返回 400（HAS_ERROR_ISSUES）
- 传 `force=true` 跳过障碍强制发布

## 请假

### 10.1 提交请假
`POST /leave-requests`（员工/店长/管理员）

请求：
```json
{ "leaveType": "PERSONAL", "startDate": "2026-09-05", "endDate": "2026-09-05", "reason": "家中有事" }
```

类型：`PERSONAL` / `SICK` / `ANNUAL` / `OTHER`

> 校验：不可重复/与已发布排班冲突/开始不早于今天/单次≤30天

### 10.2 我的请假列表
`GET /leave-requests/mine?employeeNo=`（员工可选 admin 用 employeeNo 预览）

### 10.3 请假审批列表（管理端）
`GET /leave-requests/review?status=PENDING`（AdminOnly）

### 10.4 审批请假
`PUT /leave-requests/{id}/review`（AdminOnly）

请求：`{ "approved": true, "remark": "同意" }`

### 10.5 提前返岗
`PUT /leave-requests/{id}/early-return`（仅本人）

请求：`{ "returnDate": "2026-09-08" }`

> 仅已批准（APPROVED）请假可操作；返岗日须晚于开始日期、早于原结束日期。

## 换班

请求：

## 对接注意事项

1. **认证**：所有业务接口需 `Authorization: Bearer {token}`，Token 30 分钟过期，用 `POST /auth/me` 刷新。
2. **按门店隔离**：接口自动按当前登录用户所属门店过滤数据。
3. **权限分级**：
   - 排班规则修改 = **仅系统管理员**
   - 管理端接口 = 系统管理员 + 门店经理
   - 员工端 = 登录员工本人
4. **排班问题类型**：对接方可按 `issueType` 分类处理（缺口/技能/工时/连续工作）。
5. **兼职数据**：员工 `isParttime=1` 时仅具备低技能岗位技能（保洁/咨客/传送/服务），可作为外部排班系统的兼职资源。
