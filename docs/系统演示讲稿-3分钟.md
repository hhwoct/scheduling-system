## 二、逐段时间轴（台词 + 操作）

### ⏱ 0:00 – 0:15　开场

> **讲**：大家好，我们做的是门店排班系统。过去排一次班，店长用 Excel 手工拼两三天，改一个人就得整周重排；员工想知道明天几点上班，还得翻群里的照片。我们把它变成四步：**规则一配、一键出班、店长微调、员工手机直接看**。

### ⏱ 0:15 – 0:35　首页概览

**【操作】** 点左侧「首页概览」

> **讲**：登录后是首页概览：1 家门店、33 名员工——23 名全职、10 名兼职，14 个工作站、10 个班次模板，全部是数据库实时统计，不是写死的报表。

### ⏱ 0:35 – 1:00　基础数据：人 + 规则

**【操作】** 「基础数据 → 员工管理」，点任一员工右侧「技能」，弹出技能矩阵后关掉；再点「基础数据 → 规则配置」

> **讲**：排班靠两样东西：**人**和**规则**。每个员工都带技能矩阵，14 个岗位、1 到 5 分，全店 105 条记录，分数直接决定算法把谁放到哪个岗——兼职只给低技能岗的分，就不会被排去厨房。规则共 14 条，最大周工时、连续上班上限都能按门店改。

### ⏱ 1:00 – 1:20　人数需求矩阵

**【操作】** 「店长管理 → 人数需求」

> **讲**：排班的源头是需求。这里按**平日 / 周末 / 节假日**三类日型、每半小时一个格子，配「最少 / 最好」两档人数。这张表可以 Excel 导入，也可以把一张需求文档交给 AI，自动识别成表格。

### ⏱ 1:20 – 1:55　一键排班（核心）

**【操作】** 「排班管理 → 一键排班」→ 排班方式选「未来一周」，参考日期保持今天 → 点**生成排班**（约 1 秒）

> **讲**：最关键的一步。一秒不到，一周排完——**177 条班次、2710 条半小时粒度的岗位分配，覆盖率 92%**。
>
> 背后是四阶段引擎：先按规则分配休息日；再排班次，模板不够会自动补跨午夜的临时班；然后按技能分把人分到工作站；最后插 30 分钟班中休息，自动避开 20:00–22:00 的高峰禁休时段。

> **讲（指着结果卡片）**：卡片上这几行就是这次的产出：休息日、班次分配、工作站分配、问题数、按需补的临时班数。

### ⏱ 1:55 – 2:15　发布

**【操作】** 在下方计划列表里，本行状态还是「草稿」→ 点这一行的**「发布」** → 确认框点「确定」

> **讲**：草稿状态员工是看不到的。点发布——弹窗里还会告诉你"本期手动调整了几处、发布后系统会学习这些调整"，确认之后这一周才正式生效，并推通知给员工。

### ⏱ 2:15 – 2:40　查看排班 + 问题诊断

**【操作】** 点这一行的**「查看排班」**（或结果卡片上的「查看排班计划」）→ 停在**周视图**

> **讲**：结果就是这张周视图：谁哪天几点上班、跨天班、休息时段一目了然——粉色是休息，红框是岗位缺口。右上角「问题详情」带角标，点开是完整清单：**大部分是岗位缺口**，还有班中休息顶岗的人技能不匹配、个别超工时，每条都能定位到具体日期和时段。
>
> 店长要临时调整，直接在这里换人、加人、拖动平移，每一步都能撤销。

### ⏱ 2:40 – 2:55　员工端

**【操作】** 切到手机端标签页（<http://127.0.0.1:5180>，账号 `E002 / E002@123456`）→ 右上角刷新

> **讲**：发布后手机端立刻能看到：今天几点到几点、在哪个岗位、几点班中休息，还能直接请假、申请换班，店长在审批页一键处理。

### ⏱ 2:55 – 3:10　技术收尾

> **讲**：技术上，后端 **.NET 10 + MySQL 8**，管理端 **Vue 3 + Element Plus**，手机端 **Vant**；多门店按 StoreId 隔离，JWT 加密码版本控制（改密码旧令牌立即失效），登录限流、操作全量审计。整套系统不依赖任何第三方排班引擎，**一台普通电脑就能跑，一个人就能维护**。谢谢。

## 三、万一出状况

| 情况 | 处理 |
|---|---|
| 生成按钮转圈超过 5 秒 | 直接点「查询」看列表里已有的草稿「本周排班（草稿·兜底用）」，接着往下讲 |
| 发布报「排班已发布」（或该行没有「发布」只有「取消发布」） | 说明这个周期已经发布过了，直接讲「已发布的排班员工端立刻可见」，切手机端 |
| 手机端没刷新出来 | 点右上角刷新图标；或切「周 / 月」再切回来 |
| 页面白屏 | 提前开好的备用截图顶上（`scheduling-system-env/shots/`），讲稿继续 |
| 时间被压到 2 分钟 | 砍掉「规则配置」和「人数需求」两段，保留 **开场 → 一键排班 → 发布 → 手机端** |

## 四、可能被问到的问题

1. **算法能保证最优吗？**
   不追求数学最优，追求"1 秒内可解释、可调整"。启发式 + 约束优先：硬约束（技能、工时、连续上班）先满足，再按权重优化均衡度和偏好；剩下缺口会明确列出来让店长补，而不是藏起来。
2. **数据安全怎么保证？**
   JWT 鉴权 + 密码版本号（改密码后旧令牌全部失效）、登录限流 5 次/分、手机号脱敏展示、门店级数据隔离、所有写操作进审计日志。
3. **只支持一家店吗？**
   底层是多租户（StoreId 隔离），规则支持"全局默认 + 门店覆盖"，扩门店只需加一条门店记录和它的人。
4. **和市面上的排班软件比呢？**
   轻量、可私有部署、规则完全可按门店改；不绑定 SaaS，成本低，代码在自己手里。
5. **员工年纪大不会用手机？**
   员工端只是加分项，管理端本来就能导出/打印班表；线上只是让员工少跑一趟。
6. **排出来的班不公平怎么办？**
   工时均衡是内置权重项；另外有"偏好学习"（默认关闭），会把店长手动调整过的结果当作认可样本，逐步学习这位店长的排班习惯。
