# 手机端（H5）需求确认文档

> 状态：✅ 第一版已全部完成（2026-09-02 逐页开发并验收）
> 日期：2026-09-02
> 关联项目：排班系统 MVP（后端 .NET 10 + MySQL，管理端 Vue 3 + Element Plus）

## 1. 产品定位与形态

| 决策项 | 结论 |
|---|---|
| 技术形态 | **独立移动 Web（H5）**，新建 `mobile/` 目录，Vue 3 + Vite + **Vant 4** |
| 部署访问 | 公网 HTTPS 域名，手机浏览器直接访问；**不做 PWA** |
| 门店范围 | **通用多店**：沿用现有 StoreId 多租户，页面标题随门店名显示；开发/测试以昆明滚滚为样本 |
| 目标角色 | **员工 + 店长**（STORE_MANAGER）；SYSTEM_ADMIN 在手机上登录后提示"请使用电脑端" |
| 登录方式 | 沿用账号密码（工号+密码）+ JWT；忘记密码（姓名+手机号双验证）；登录后可自助改密 |
| 登录保持 | **JWT 7 天 + 不做无操作自动登出**（后端 Jwt:ExpireMinutes 上限 1440 → 10080） |
| 通知触达 | 仅站内通知：进入页面拉取 + 下拉刷新 + 前台 30~60 秒轮询未读角标；浏览器标题随未读闪烁 |

## 2. 角色功能矩阵

### 2.1 员工端页面（EMPLOYEE）

| 页面 | 功能 | 要点 |
|---|---|---|
| 登录/忘记密码 | 工号+密码登录；忘记密码（姓名+注册手机号双验证重置） | 与 PC 端同一套 /auth 接口 |
| 我的班表（首页） | **今天+本周卡片优先**：首屏今日班次大卡片（班次时间、岗位、班中休息），本周班表列表，可切月历；点某天看日详情（含顶岗人）；「我顶岗的记录」入口 | 默认近 30 天数据，复用 /employee/my-schedule |
| 我的请假 | 请假列表（按状态筛选/标签）、提交请假（类型：事假/病假/年假/其他 + 起止日期 + 事由）、详情页、**提前返岗**（已批准的可缩短） | 第一版**不上传凭证图片** |
| 换班 | 我的换班列表（状态：待审批/已同意/已驳回）、发起换班：选日期 → 系统列出当天休息的同事（候选）→ 选择 + 事由 → 提交 | **沿用现有流程**：直接送店长审批，不加"对方确认"环节 |
| 通知中心 | 消息列表、未读角标、单条/全部标记已读 | 排班发布、审批结果、换班结果 |
| 我的 | 个人信息、修改密码、退出登录 | |

### 2.2 店长端页面（STORE_MANAGER）

| 页面 | 功能 | 要点 |
|---|---|---|
| 全店排班（首页） | **默认直接进本周全店排班**：周视图（可切月视图），点某天看日明细（全员班次+岗位+休息+班中休息） | **只读**，复用 /schedules/{planId}/week-view、month-view、daily-view |
| 请假审批 | 待审批列表 + 已处理列表；详情：同意/驳回 + 审批意见 | 复用 /leave-requests/review |
| 换班审批 | 同上（申请人、换班对象、日期、事由） | 复用 /shift-swaps/review |
| 排班发布/退回 | 排班计划列表（草稿/已发布状态）；发布确认弹窗（显示问题诊断数）；已发布可退回草稿并通知员工 | 复用 publish/unpublish |
| 员工通讯录 | 员工列表：工号+姓名+部门+岗位，支持搜索 | **不显示手机号**（保持脱敏），无拨号 |
| 通知中心 | 同员工端 | |
| 我的 | 店长自己的班表/请假/换班（店长本身也是员工档案 E001，复用员工端功能）、修改密码、退出登录 | |

### 2.3 第一版明确不做（留 PC 端）

- 手机端**排班调整**（空位加人/取消班/换人/改休/平移等一切调整操作）——只读+审批
- 一键生成排班
- 排班规则 / 人数需求矩阵 / 日期参数 配置页
- 员工管理 / 技能矩阵 编辑
- 报表 / 偏好学习分析
- 请假凭证拍照上传
- 外部推送（短信/微信/Web Push）
- 系统管理员（SYSTEM_ADMIN）移动端功能

## 3. 接口复用与后端改动

### 3.1 完全复用（现成接口，无后端改动）

- 认证：/auth/login、/auth/forgot-password、/auth/change-password、/auth/me、/stores/current
- 员工：/employee/my-schedule、/employee/swap-plans
- 请假：POST /leave-requests、/leave-requests/mine、/leave-requests/{id}/early-return
- 换班：POST /shift-swaps、/shift-swaps/mine、POST /shift-swaps/candidates
- 通知：/notifications、/notifications/unread-count、/notifications/{id}/read、/notifications/read-all
- 店长：/schedules、/schedules/{planId}/week-view、month-view、daily-view、/leave-requests/review、/shift-swaps/{id}/review、/employees、publish、unpublish

> 权限已确认：后端 AdminOnly 策略 = SYSTEM_ADMIN + STORE_MANAGER，店长审批/发布/查看全部可用。

### 3.2 需要后端配合的小改动（共 2 处）

1. **JWT 有效期放宽**：Jwt:ExpireMinutes 上限 1440 → 10080（7 天），移动端长登录。
2. **/employee/my-schedule 的 Days 增加 WorkstationId / WorkstationName 字段**：手机端"今日卡片"需显示岗位（如"14:00-22:00 · 服务台"）。

## 4. 关键交互约定

- 员工首页"今日卡片"：有班 → 班次时间 + 岗位 + 班中休息时段；休息 → "今日休息"；同时预告下一个班次
- 店长首页直接进全店排班周视图，待审批数量在页面入口/角标提示
- 通知未读：底部 Tab 红点 + 浏览器标题闪烁（前台轮询 30~60 秒）
- 移动端不做 15 分钟无操作登出（与 PC 区分）
- 换班候选逻辑与后端一致：列出换班当天**休息**的同事（排除自己）
- 移动端路由按角色：EMPLOYEE → /employee 区，STORE_MANAGER → 店长首页，SYSTEM_ADMIN → 提示用 PC

## 5. 开发与交付方式（逐页推进）

- **逐页开发、逐页验收**：每完成一个页面/流程 → 本地跑通 → 手机浏览器验收 → 确认后再做下一页
- 建议顺序：
  1. 项目骨架 + 登录/忘记密码/退出
  2. 员工-我的班表（今日卡片+周/月+日详情）
  3. 员工-请假（列表/提交/详情/提前返岗）
  4. 员工-换班（列表/发起/候选）
  5. 员工-通知中心
  6. 员工-我的（改密等）
  7. 店长-全店排班（周/月/日只读）
  8. 店长-请假/换班审批
  9. 店长-排班发布/退回
  10. 店长-通讯录
- 本地联调：后端 localhost:5000 + 移动端 dev server，手机与电脑同网段以局域网 IP 访问验收

### 关键实现说明

- 移动端与 PC 端共用同一套 localStorage 键与 /api 代理约定；生产部署可同域名分路径
- 验收地址：手机与电脑同一局域网，浏览器打开 http://<电脑IP>:5180
