## 二、高优先级问题（🟠）

### 后端

**2.1 日状态调整非原子：先删后建无事务，失败即损坏当天排班明细**
- 位置：`backend/ShiftScheduling.Api/Application/Schedules/ScheduleService.cs:616-777`（SetDayStatusAsync）
- 问题：`ExecuteDeleteAsync`（第 621-623、716-718 行）**立即落库、不参与 ChangeTracker**，而新增明细要等循环结束后的 `SaveChangesAsync`（第 777 行）才提交，两者之间无事务。批次内任一后续条目抛 BusinessException（如工作站校验失败），前面条目已删除的明细不会回滚——出现「明细已删、汇总未改」的数据损坏。
- 建议：整段包 `BeginTransactionAsync`；或改用跟踪实体删除与新增在同一 `SaveChangesAsync` 提交。

**2.2 通知已读接口水平越权：员工可标记门店级通知为已读**
- 位置：`Program.cs:1130`
- 问题：`query.Where(x => x.ReceiverEmployeeId == emp.Id || x.ReceiverEmployeeId == null)` —— `== null` 分支把门店级通知（管理员可见的「新请假/新换班」提醒）也纳入，员工按 ID 即可越权改变他人通知状态。
- 建议：员工分支改为仅 `ReceiverEmployeeId == emp.Id`。

**2.3 员工档案缺失时「全部已读」会清空全店未读通知**
- 位置：`Program.cs:1152-1165`
- 问题：员工档案查不到（停用/删除）时 `emp == null`，`query` 保持「门店下全部未读」，随后 `ExecuteUpdateAsync` 把整店未读全部置为已读；且两处员工查号（1127、1155 行）缺 `StoreId` 过滤。
- 建议：档案缺失时直接抛错或 `query.Where(x => false)`；查号补 `StoreId`。

**2.4 登录/重置限流是全局单桶，未认证用户可 DoS 全店登录**
- 位置：`Program.cs:158-177`
- 问题：`AddFixedWindowLimiter("LoginLimiter"/"ResetLimiter")` 未提供按 IP 的分区器，ASP.NET Core 默认使用**全局单一分区**——登录 5 次/分钟、重置 3 次/15 分钟是**全店共享**配额。任何人连发 5 个登录请求即可让全店 1 分钟内无法登录。
- 建议：改用 `options.AddPolicy("LoginLimiter", ctx => RateLimitPartition.GetFixedWindowLimiter(ctx.Connection.RemoteIpAddress?.ToString(), ...))` 按 IP 分区。

### 前端

**2.5 拖拽移动工作段功能因引用未定义变量 seg 整体失效**
- 位置：`frontend/src/views/ScheduleView.vue:371`
- 问题：`dragMove.targetSlotIdx = seg.start`，seg 全文件未定义，mousedown 即抛 ReferenceError，且该行在幽灵块/起始坐标赋值之前，整个「拖动移动半小时工作段」链路断裂。
- 建议：改为 `dragMove.targetSlotIdx = slotIdx`（第 361 行已算出的下标）。

**2.6 依赖 xlsx@0.18.5 含已知 CVE，且用于解析用户上传的 Excel**
- 位置：`frontend/package.json:20`
- 问题：xlsx 0.18.5 存在 CVE-2023-30533（原型污染）、CVE-2024-22363（ReDoS），修复版仅在官方 CDN（0.19.3+/0.20.x）发布；本项目用它在 StaffingRequirementsView 解析用户上传文件，属现实攻击面。
- 建议：升级到 SheetJS 官方源的 0.20.x，或换用 exceljs。

**2.7 忘记密码功能完全不可用：前端不传 OTP，后端必拒绝**
- 位置：`frontend/src/views/LoginView.vue:34-51,140-145` + `backend/.../Auth/AuthService.cs:181-184`
- 问题：前端重置对话框只有用户名/手机号/新密码字段，没有 OTP 输入框，也不调用 /auth/send-reset-otp；后端 ForgotPasswordAsync 要求 OtpCode 非空。**任何情况下重置都会失败**（「验证码不能为空」）。且生产环境 OTP 既不返回也不发短信（仅非生产写日志），密码重置在线上不可用。
- 建议：补齐前端「获取验证码 → 输入 OTP」两步流程；生产接入短信网关后再开放该功能。

### 数据库

**2.8 补班日 2026-09-27 被误标为法定节假日**
- 位置：`database/migrations/20260818_add_weekend_staffing.sql:24-26`
- 问题：`SET is_legal_holiday = 1, day_type = 'WORKDAY'` 与自身注释（第 9、19 行「09-27 调休补班按平日」）矛盾，会影响所有读取 is_legal_holiday 的算法/薪酬逻辑。
- 建议：改为 `is_legal_holiday = 0, day_type = 'WORKDAY'`。

**2.9 init_shift_mvp.sql 与迁移链双向不同步**
- 位置：`database/init_shift_mvp.sql` 多处
- 问题：(a) init 缺迁移链已创建的对象：表 shift_swaps、leave_requests、peak_restricted_hours；列 users.password_version、rule_configs.version、schedule_results.assignment_key、schedule_summaries.break_*；唯一约束 schedule_plans(store_id, plan_name)——用 init 建库后再跑迁移会失败；(b) init 又已吸收 08-12/13/19/21/22 迁移（ideal_count、remark、is_low_skill、is_generalist、E101~E110 兼职），对这些已吸收项重跑迁移会报重复列/重复键。
- 建议：把 init 补全为「全量基线」并声明吸收清单；或让 init 只做骨架、不吸收迁移内容，并强制「init 后必须按序执行全部迁移」。

**2.10 20260819 幂等性声明不实**
- 位置：`database/migrations/20260819_add_ideal_count.sql:5,10-11`
- 问题：头注称「重复执行无副作用」，但 ALTER TABLE ADD COLUMN ideal_count 无 IF NOT EXISTS（MySQL 8.0 不支持），二次执行报 Duplicate column。
- 建议：删除错误声明或引入 schema_migrations 版本表防重。
