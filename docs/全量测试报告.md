## 四、发现的问题（第 1 项已修复）

### 1. 【已修复】闭店空窗 06:00 幽灵时段（原 P2，提交 `71e8595`）
**根因**：人数需求里保洁岗误配了打烊后时段 `06:00` 的 `required_count=1`（3 行），引擎按缺口生成 D 临时班次 → 每个计划每天多 1 条 `time_slot='06:00:00'` 的明细，超出日明细时间轴（13:00~次日 05:30），界面不可见。
**修复**：
- 引擎输入净化：`SchedulingEngine.Execute` 剔除打烊时段（06:00~12:30）的需求，防止误配复发；
- 迁移 `20260827_fix_0600_out_of_axis.sql`：清零 3 行误配需求、删除历史 72 条幽灵明细、7 条陈旧缺口、2 条空壳汇总（幂等）；
- 新增回归测试 `ClosedMorningDemandTests`（235 测试全绿）。
**验证**：重新生成计划 → 06:00 明细 0 条、缺口 0 条；工作站明细 2255→2248（-7）、需求覆盖 953→949.5 人·时（-3.5），与移除的幽灵段精确吻合；日明细交互回归 8/8 通过。

### 2. 【提示】默认密码 工号@123456 不满足"含小写字母"策略
初始密码（迁移直写 DB）为 `工号@123456`（无小写字母），但忘记密码/修改密码表单的策略要求"大写+小写+数字"。员工无法通过表单把密码设回默认值（提示性不一致，非安全漏洞；表单策略本身正确）。
