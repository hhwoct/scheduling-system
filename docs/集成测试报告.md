## 4. 关键验证点（亮点）

- **OTP 全流程端到端**：发送验证码 → 从服务端日志提取 `[DEV-OTP]` → 重置 → 新密码登录 → 旧密码失效 → OTP 单次有效（复用被拒）；弱密码/密码不一致/错误手机号/不存在用户均正确拦截（统一消息防枚举）
- **失败锁定**：第 5 次错误密码触发锁定 15 分钟，锁定期间正确密码也被拒
- **登录限流**：每 IP 每分钟第 6 次登录被 429 拦截
- **换班事务互换**：审批通过后 E002（上班→休息）与 E003（休息→上班）班表完整互换（含班次 S1 13:00-22:00 与班中休息），重复审批被原子抢占拦截
- **拖动移动**：合法移动成功（30 分钟吸附）、目标重叠 400、无技能工作站 400、还原成功
- **级联删除**：删除 3 个计划后 schedule_results（6011 行）/summaries（2305）/issues（249）/shift_swaps 全部清零（DB 验证）
- **乐观锁**：规则配置 version 冲突 → 400「规则已被他人修改」
- **安全**：手机号脱敏（138****0001）、员工访问管理接口 403、无效 token 401、AI 配置 SSRF 拒绝（http 地址被拦）

## 9. WORKDAY 平日需求修复（数据缺陷）

**缺陷**：staffing_requirements 中 `WORKDAY`（周一~周四+周日）624 个时段需求全部为 0——8-6 初始化时旧版 init_shift_mvp.sql 未配置平日需求，8-18 迁移拆分 WEEKEND 时只复制了 HOLIDAY→WEEKEND，WORKDAY 从未回填，导致**工作日不排任何班**（8-24 日明细 0 行）。

**修复**：新增 `database/migrations/20260819_fix_workday_staffing.sql`，按当前 init 脚本业务口径重算 WORKDAY 全时段（行政岗 13:00-22:00=1、厨房 18:00-23:30=2、服务/传送 19:00-23:30=2、吧台 18:30-23:30=1、保洁 21:00-06:00=1 等，含审计留痕，幂等可重跑）。
